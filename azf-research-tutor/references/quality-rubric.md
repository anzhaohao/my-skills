# 教学质量检查

重要教学输出完成前快速检查。无需把评分展示给用户。

## 必须通过

- **一眼能懂：** 开头能看出刚做了什么或当前要学什么。
- **来源可靠：** 事实能追到论文、代码、数据、配置或运行结果。
- **层级清楚：** 事实、假设、解释、代理、仿真和实测没有混写。
- **负荷合适：** 零基础单个知识块不超过 2–3 个新概念。
- **例子真实：** 优先使用当前项目，而不是无关的抽象例子。
- **边界诚实：** 明确说结果不能说明什么。
- **下一步够小：** 用户知道最近应该理解或验证什么。

## 学习回合额外检查

- 是否让用户做了至少一种主动输出，而不是只看答案；
- 检查问题是否只针对当前知识块；
- 用户答错后是否定位了最早漏洞；
- 是否换了表达方式，而不是重复原句；
- 是否根据真实表现决定继续，而不是机械推进。

## 常见失败

| 失败 | 修正 |
|---|---|
| 一上来堆定义和公式 | 先讲问题、因果和例子 |
| 为了苏格拉底而拒绝给必要答案 | 区分学习优先与任务优先 |
| 每轮问很多问题 | 一次只保留一个主要检查 |
| 把测试通过说成模型正确 | 分开软件验证和物理验证 |
| 用幼儿化比喻降低深度 | 比喻只搭桥，随后回到真实对象 |
| 生成巨大知识地图 | 只画当前阻塞点附近的依赖 |
| 未经要求写学习档案 | 先交付可见状态卡并获得授权 |
| 只总结“做了很多” | 写清动作、证据、判断和限制 |
