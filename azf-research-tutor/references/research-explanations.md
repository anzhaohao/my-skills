# 科研内容怎么讲

## 概念

按“它是什么 → 为什么需要 → 在当前项目中做什么 → 一个例子 → 容易混淆什么”讲。定义不能代替解释。

## 公式

按以下顺序：

1. 先用一句话说公式描述的关系；
2. 逐个解释符号的实际含义和单位；
3. 说明一个量增大时结果通常怎样变化；
4. 代入当前项目的一个真实数字；
5. 说明公式依赖的假设和失效范围；
6. 最后再展示完整公式或推导。

不要只做符号翻译。必须让用户知道公式在程序或实验哪一步使用。

## 论文

先分清：

- 作者想解决什么；
- 做了什么；
- 直接观察到了什么；
- 作者如何解释；
- 哪些数据或代码公开；
- 哪些结论能迁移到当前项目；
- 哪些条件不同，不能照搬。

引用时优先给论文原文、补充材料、图表、公式编号或代码入口。二手解释只能作为辅助。

## 代码

先讲文件或函数的角色，再讲细节：

```text
输入数据从哪里来
→ 经过哪个模块
→ 做了什么转换
→ 输出保存到哪里
→ 用什么测试证明没有明显算错
```

只展示能解释当前问题的最小代码块。说明变量的人话含义，不逐行朗读语法。

## 仿真

必须分开五层：

1. **现实对象：** 真正的光学、材料或实验过程；
2. **模型：** 选择用什么关系近似现实；
3. **输入：** 参数来自论文、测量、标定还是人为设定；
4. **输出：** 直接计算量、代理指标和风险标志；
5. **验收：** 用什么已知趋势或数据检查方向。

始终指出模型忽略了什么。通过程序测试只说明实现符合预期，不等于物理模型正确。

## 结果与图

先说图的横轴、纵轴和每个点代表什么，再说肉眼能看到的事实，最后才给解释。按以下格式：

```text
图在比较什么：
直接看到什么：
当前解释：
替代解释或限制：
下一步怎样验证：
```

## 实验与 DOE

按“研究问题 → 改哪些因素 → 测什么结果 → 如何控制干扰 → 怎么判断 → 失败后怎么办”讲。

区分独立重复、同一条件下连续采帧和重复计算。没有真实时间序列时，不把参数扰动敏感度叫作实验稳定性。
