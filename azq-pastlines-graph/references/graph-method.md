# 图谱抽取与验收方法

## 目标

先做一张“能读、能查、能改”的基础图，不追求一张图讲完所有细节。节点少一点、关系有证据，比节点多但含义混乱更有用。

## 1. 定边界

先写范围说明：

- 纳入哪些页、段落或小节。
- 排除哪些相邻内容。
- 这张图回答什么问题，例如“四趟远航的先后与因果”或“一个概念的组成”。

范围不清时，先向用户确认，不要用整本书自动扩图。

## 2. 抽节点

候选类型：

- 事件：航行、战争、改革、协议、发现。
- 人物：航海家、统治者、思想家、群体代表。
- 地点：国家、港口、海域、区域。
- 群体：商人、船队、阶层、组织。
- 概念或制度：航线、协定、政策、技术。
- 史料或证据卡：只在需要单独呈现证据时使用。

粒度检查：

- 这个节点能否用一句短标题说清？
- 它是否有独立来源，而不是只从另一个节点推断？
- 删除它会不会让图读不懂？不会就不要加。

## 3. 抽关系

先问“原文明确说了什么”，再选类型：

- 原文有“因为/因此/导致/使得” → 可考虑 `causal`。
- 原文有明确先后 → 可考虑 `temporal`。
- 原文在比较两个对象 → 可考虑 `comparison`。
- 原文说部分属于整体 → 可考虑 `membership`。
- 只是读者联想、教材没有明说 → `pending`。

每条边至少写一句 `evidence`。如果证据只能支持“相关”，不要写成“因果”。

## 4. 审查

- 合并同义节点：别名、全称简称、同一事件的不同叫法。
- 删除重复边：同一对节点、同一含义只保留一条。
- 检查方向：因果是否从因到果，时序是否从早到晚。
- 检查孤立点：要么补关系，要么在交付说明里标为“上下文卡”。
- 检查数量：基础图 12–24 个节点较舒适；超过 40 个拆图。

## 5. 布局

脚本默认按关系方向分层：

- 左侧是较早或上游节点，右侧是较晚或下游节点。
- 同一层从上到下按输入顺序排列。
- 不同连通分量上下分区，避免叠在一起。

布局只解决“能读”，不替代人工判断。打开后如果线穿过卡片、文字被裁切或两组内容混在一起，先调整节点顺序或拆分，不要只把缩放调小。

## 6. 验收

至少检查：

- 项目能打开，节点和关系数量与 plan 一致。
- 没有 schema 报错。
- 每个节点有来源，每条边在 plan 里有证据。
- 1440×900 和 1024×768 下，主要内容在画面内。
- 关系方向读得通；没有把“相关”写成“因果”。
- 没有为了凑数而添加的节点。

脚本通过只说明格式、引用和布局通过；内容是否准确必须对照原文。

## 常见坏图

- 每个段落一个节点，节点名是一整句话。
- 所有边都标 `causal`，但没有原文因果词。
- 节点很多、关系很少，图变成卡片清单。
- 关系线绕来绕去，读者找不到起点。
- 来源写“教材”或“网上”，没有页码、段落或原文。
