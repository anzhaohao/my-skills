# azf-obsidian-project-record

这是安钊锋 Obsidian 项目记录系统的**规则权威层**。规则细节以同目录 `SKILL.md` 为准；`00-Command Center/笔记库规范/2_项目规范/项目笔记AI协作需求（草案）.md` 只做导航、机制索引和验收场景，两者冲突时以 `SKILL.md` 为准。

## 这个 skill 解决什么问题

把一个项目整理成「总览、主线、调试记录、项目理解、补充资料」几层，让以后重新接手时先看懂当前状态，再顺着主线理解每条记录之间的关系；同时规定 AI 在刷新项目状态、做事前复用检查、把结论写回笔记时**该做什么、能写什么、不能写什么**。

硬件资产卡片由 `E:\software\Obsidian\安钊锋的外置大脑\03-Academic Toolkit\2_资源与档案\仪器设备资产` 手动维护，不属于本 skill 的写入范围。

## 什么时候触发

- 新开项目、建立项目总笔记、整理项目笔记、维护或同步调试记录。
- 项目文件夹在 `01-Project` 下，需要拆分、编号、移动或同步链接。
- 提供实验截图、GUI 状态图、硬件状态图、报错、结果图，需要写入 Obsidian。
- 说「新项目也按这个方式记录」「同步调试记录」「帮我把记录整理清楚」。
- 说「刷新当前项目」「刷新当前阶段」「复用检查」「这个是不是做过了」。
- 希望新项目从一开始就有 FrogTrace 那种「总览清楚、主线清楚、调试记录归位、图片不断链」的效果。

## 现在这套系统的骨架

**三层职责**：总笔记＝当前状态视图；主线笔记＝把记录串成一条推进线索；调试记录＝时间线证据。项目理解与补充资料放相对稳定的知识。

**视图与依据分离**：AI 简报 callout、阶段摘要这类内容可以在每次刷新时重写；调试记录正文、主线推进记录、你的决定只能追加，结论改变时保留早期记录原样。

**写入权限闸门**：vault 默认只读。只有你明确要求记录/整理/同步/刷新，或你确认了一次整理，或你自己运行了刷新动作，才允许写笔记。日常改代码、调试、看日志时只读，并如实说明「笔记同步待处理」。

## 关键规则速查

1. **复用检查优先**：在提出下一步之前，先比对历史工作记录的目标、对象、条件、批次和产出，输出三件事——已覆盖什么、差异是什么、可复用什么还缺什么，每条都要写出依据的笔记名。没有来源就不许说「做过」。
2. **归属判断**：能接已有主线的记录只补 `关联主线`（**不写** `归类状态`，缺省即已归类），同时追加到该主线 `推进记录`；接不上的才写 `归类状态: 未归类` 并说明原因。Q 卡片只做状态入口，不放过程历史。
3. **刷新动作**：读主线属性与正文、近期工作记录正文、问题库受管区；写面只有三处——总笔记锚点内的 callout、`0_总览/当前阶段记录/<项目名>当前阶段记录.md` 的周条目、白名单 frontmatter 字段。
4. **幂等**：callout 只替换不叠加；没答复的「需要你决定」条目合并去重、最多 8 条；周记录每次运行追加一条是审计轨迹，不算重复。
5. **冲突不覆盖**：写字段前比对本次上下文读取的快照，文件在刷新期间被改过就跳过并报告；callout 被手工改过时先弹「覆盖 / 保留当前内容」，选保留就一个字都不动，绝不静默覆盖人工改动。
6. **模板优先**：创建或更新项目笔记必须调用当前发现的 Templater 模板，禁止手写或复制历史模板体。
7. **事实与判断分离**：你的决定、实测结果、AI 推断三者要分清；建议 ≠ 决定 ≠ 已完成。
8. **状态说真话**：问题库状态是 `待处理 / 处理中 / 阻塞 / 待验证 / 已完成`；代码或方案写完但还没实机、验收证据的一律 `待验证`，只有证据到手才写 `已完成`。
9. **编号不重排**：问题库的 Q 编号固定，删除后留空号，新增 = 当前最大编号 +1，正文里写「Q18」可以长期引用。

## 机制与字段对应（速查）

| 机制 | 位置 / 取值 |
|---|---|
| 阶段 callout 锚点 | 总笔记内 `%%azf-stage:begin%%` … `%%azf-stage:end%%`；真实项目里手工放在 `# 一、现在先看这里` 内；默认**折叠**，标题写成 `> [!azf-stage]- 当前阶段：<一句话现状>（更新于 …）` |
| 阶段卡片冲突 | 刷新前与周记录里最新一条比对（忽略标题行与「需要你决定」小节）；不一致就问「覆盖 / 保留当前内容」 |
| 待决定溢出 | 上限 8 条，被挤出的仍在周记录里，卡片末尾提示「另有 N 条较早的待决定」 |
| 问题表结构 | 列＝编号／事项／类型／状态／主线入口／操作；没有描述列，单击行展开说明、单击说明即可编辑；工具栏有「隐藏已完成」 |
| 时间线范围 | 只画主线节点与未归类支线，**工作记录不上时间线**；缩略图只显示最近 `thumb-nodes`（默认 6）条主线，大图是横向画布可滚动或拖动 |
| 周记录 | **每周一个文件**：`0_总览/当前阶段记录/<项目名>当前阶段记录 <周键>.md`（如 `FrogTrace当前阶段记录 2026-W38.md`）。一级标题就是那一周并带日期范围（`# 2026-W38（09-14 ~ 09-20）`），frontmatter 带 `项目名称` / `覆盖周` / `项目笔记类型: 当前阶段记录`，同周新的在上；历史单文件（含多周）与更早的平铺文件在第一次刷新时自动拆开 |
| 更新哪篇总笔记 | **锚点决定**：①你正在看的那篇（无锚点会先问你要不要插入）→ ②名字唯一的 `<项目名>项目总笔记` → ③唯一带锚点的候选 → ④唯一候选；仍多个就报错并标注各候选有无锚点。既没锚点又没声明 `项目笔记类型: 项目总览` 的笔记会被拒绝并提示 |
| 机器写入块 | 简报末尾 `%%azf-writes%%` … `%%azf-writes:end%%`，原样留在周记录里做审计 |
| 可写字段（记录） | `关联主线`；`归类状态` 只在写 `未归类` 时出现 |
| 可写字段（主线） | `推进状态`、`当前状态`（`下一步` 已不再是字段） |
| 上下文预算 | 插件设置 `contextBudget`，默认 80000 字符；保留顺序：问题库 → 工作记录正文 → 主线正文 |
| 上下文窗口 | 插件设置 `weeks`，默认最近 4 周 |
| 后端 | 默认本地 Codex CLI（仅桌面，无需密钥）；可切 OpenAI 兼容端点 |
| 提示词默认值 | 保存过的提示词不会被默认值覆盖；设置页每个提示词右侧有「恢复默认提示词」按钮（只改本机设置，不动笔记） |
| 相关命令 | `azf-stage-refresh`（刷新当前阶段并做复用检查）、`azf-board-open`（打开看板） |
| 执行插件 | `.obsidian/plugins/azf-issues-db`（v0.6.0） |
