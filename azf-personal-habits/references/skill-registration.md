# 适用范围与职责

创建自建 skill、安装或接管第三方 skill、补登记，以及检查更新后的登记状态时，先按本清单收尾。`azf-personal-habits` 维护个人约定；原版 `manage-skills` 提供受支持的管理器命令。不要将本清单写回第三方 skill。

# 本机入口与收纳

- 当前 Windows 中央库：`E:\software\skills-manager\skills`，真实文件只放这里。先用管理器 `--json repo status` 核对配置，不把上游文档里的默认路径当成本机实际目录。
- 固定 CLI 桥接：`C:\Users\anzhaofeng\.skills-manager\bin\skills-manager-cli.exe`。先检查同目录 `.version` 与二进制齐全，遵循原版 `manage-skills` 的桥接版本核验规则；解析输出时传 `--json`。
- E 盘中央库不可用时先报告，不创建平行技能库。上述 Windows 路径不应直接套用到其它机器。
- 只收已确认的第三方和自建技能。Harness 自带、默认及 OpenAI/Codex、Anthropic/Claude 官方原生技能保留在所属原生目录；来源未确认时先不归入“通用技能”。参考目录中嵌套的 `SKILL.md` 不自动视为独立技能。

# 登记与预设核验

1. 查重：按目录名、frontmatter `name`、解析后的真实路径和来源查询 `--json skills list` 与 `--json skills show <name-or-id>`。已有记录复用原 ID；同名异源或内容不同先比较，不为补登记而删除重装。
2. 区分文件和记录：有目录及 `SKILL.md` 不代表已登记。本机 `azf_auto_general_preset_after_insert` 只在数据库新增记录后自动归组，不会监控新建文件夹。规则定义和恢复说明在 `E:\software\skills-manager\maintenance`。
3. 安全入库：优先使用管理器支持的安装或接管操作。对于已创建但未登记的单个目录，先运行 `--json skills adopt <source-path> --dry-run`，确认目标属于可接管列表而不是被跳过。只用真实来源，不伪造 Git 上游，不手写数据库或可移植登记文件。
4. 保护原文件：操作前外部备份整个技能目录及 supporting resources，比较前后内容哈希。v1.43.4 不要盲目将同一个中央目录同时作为导入源和目标；同目录自导入可能被拒绝或进入替换逻辑。已有客户端链接仅在确认当前版本识别同一真实目标并保留文件后，才可作为接管入口；dry-run 成功本身不证明实际导入安全。不能为获得入口先扩大部署。没有可验证的安全路径时保留原状并报告“文件已创建，尚未登记”。
5. 核验唯一记录、真实来源及 `.skills-manager/skills/<id>.json` 可移植登记文件。更新已有记录不再次调用 `adopt`，不重设来源或删除 ID。
6. 通过 `--json presets show "通用技能"` 核对成员关系；遗漏时使用 `--json presets add-skill "通用技能" <skill-name-or-id>`。同时确认 `.skills-manager/scenario-skills/<preset-id>/<id>.json` 成员元数据存在，不仅依赖自动归组。

# 保留部署状态

登记与归组不授权 `deploy`、`sync`、`presets apply`、启用客户端、切换活动预设、替换现有副本或迁移其它机器。保留现有部署记录、客户端路径、链接和来源关联；Mac 迁移按独立请求处理。

只有当前任务授权整理客户端目录时，才先记录每处原有技能名单、合并独有修改并做外部备份，然后在原路径替换为指向中央库的链接。共享目录和旧路径也保留原范围，不整组开启预设，不添加其它客户端或另一默认根目录部署。插件缓存和 Harness 原生内容遵循本 skill 主文的归属规则。

# 上游更新与个人规则

上游维护的第三方 skill 保持对应版本原样，不在其中添加本机规则或上游没有的中文 README。自建 skill 继续维护中文 README。`manage-skills` 的更新、来源和部署功能通过原版管理器执行，本清单只叠加个人要求。

已有本地定制时，先比较并外部备份，将个人规则迁回自己的 skill；恢复第三方原版须有用户授权。管理器报告 `held_back_removals` 时，核对具体文件，不能因已经备份就自行认定可删。CLI 更新会整目录替换，同路径的本地修改也可能被覆盖；不能只检查“将删除”的文件列表。

# 完成报告与备份

分别报告：真实文件、登记 ID、预设成员、部署变化、本地提交、远端备份。登记失败必须写明“文件已创建，尚未登记”及具体原因。

推送已获授权或既有自动备份运行时，核对实际提交范围与远端版本再声明备份完成。只提交本次修改，不改写已发布的自动备份提交。本地提交成功不代表远端已收到；回滚备份仍放在中央库外的 `E:\software\AI改前备份`。
