# azf-manager-builder

## 这个 skill 解决什么问题

把"只能敲命令启动、挂了得手动重启"的本地项目，变成一个**单文件 Windows 托盘管理器（.exe）**在托管：开机自启、端口级健康检查、挂了自动拉起、托盘能看状态和重启、脚本能通过命令行控制。

它来自 2026-09-22 给 `20260922-codex-router` 做 `CodexRouterManager.exe` 的实战经验——那套东西你已经很满意，这个 skill 就是把同一套做法**可复用化**，以后部署新项目时能照着造一个。

## 什么时候应该触发

- 部署、接手、或者"帮我托管/守护"一个本地项目；
- 项目有**长驻进程**（网关、守护、本地 API、隧道、监听器、常驻 Web 服务），但只有命令行的启动方式；
- 你说"开机自启""别老让我手动重启""给我弄个托盘管理器"；
- `azf-personal-habits` 的部署检查发现"有长驻进程但没有管理器"。

**不触发**：一次性脚本、纯 CLI 工具、已经由 Docker/服务管理器/现成管理器托管的项目、要求做成 Windows 服务（session 0 没有桌面，托盘和电脑操作都用不了）。

## 部署时的动作顺序（这是你在 personal-habits 里要的入口）

1. **先扫**：按 `reference/manager-detection.md` 判断原项目有没有管理器/托管机制；
2. **分类**：已托管 → 只报告；只有启动器（`.bat`/`.ps1`/`.vbs`，启动一次不管死活）→ 目标场景；没有长驻进程 → 一句话说明"无需管理器"继续；
3. **问**：目标场景下**先停下问你**"要不要顺手建一个 .exe 管理器"，并把要托管的进程、端口、会生成的文件、回滚方式一并说清；
4. **得到同意才动手**：按 `SKILL.md` 的 Step 2/3 生成 + 真实杀进程演练验证；
5. **交接**：README/PROGRESS 写清托盘菜单、CLI 契约、状态文件与日志位置、回滚命令。

## 当前保存的关键事实

- 产物形态：`.NET Framework` 自带 `csc.exe` 编译的 `/target:winexe` 单文件 exe，**零依赖**（不装 SDK、不拉 NuGet）；
- 能力基线（与 `CodexRouterManager` 对齐）：N 个子进程、5 秒端口级健康检查、退避 5/15/60/300 秒**且健康后归零**、启动清理孤儿端口、单实例互斥、状态 JSON、日志轮转、托盘状态色与菜单、脚本友好 CLI（`--status/--stop/--restart/--headless/--fix-*`）、可插拔自愈钩子；
- 计划任务：登录触发 + 延迟 + 失败重启 + 不限时长；**旧启动方式停用但保留**用于回滚；
- **形态（2026-09-24 你拍的板）：一个项目一个 exe**。托盘体验一致，但各项目各自一个进程、互不牵连；**不做通用模板、不做脚手架框架、不做"一个 exe 管所有项目"的全局管理器**。做法就是复制 `20260922-codex-router\local\manager\` 那套，改掉进程命令、端口、`.env` 路径、状态/日志路径、以及**六项身份标识**（exe 名、互斥体、计划任务名、状态文件、日志文件、托盘图标）——详见 `reference/hardening-checklist.md` 第 13 条。

## 现状扫描（2026-09-24，DevLab 24 个项目）

只有 `20260922-codex-router` 有真正的管理器；`20260828-ctxedkbh-paper-workbench`（`启动桌面版-无控制台.bat` + `autostart.vbs`）、`20260715-ai-paper-weekly`（计划任务 `run-scheduled.ps1`）属于"类似但无自愈"；其余多数是要手动重启的启动脚本。这正是这个 skill 存在的原因。
